Large-display behaviour

Content caps at 1920px and centres; the rule under the header and the rule above the footer run the full window width. One rule, no new column counts, and the design reads the same on a 24" and a 32" display.

Implementation

One max-width: 1920px; margin-inline: auto on the header content, the body, and the footer content, applied at every width. Below 1920 it has no effect, so no media query is needed for this breakpoint. The header's own border-bottom and the footer's own border-top move to the full-width bands.

Case Studies/Linode

Linode Cloud Manager

Designing an interface to manage a single VPS or a fleet of thousands

Vertical
Cloud Hosting
Platform
Responsive Web
Expertise
User Research / Information Architecture / UX Design / Usability Testing

Linode is an innovative cloud hosting provider that made their name as an affordable, developer-focused VPS service. Their browser-based administration panel, known as Linode Manager, was designed in-house by the company's engineers to be a fast, no-frills interface for customers to manage their virtual machines, domains, and other cloud assets.

User Interviews

I partnered with Customer Success to identify users who represented a broad spectrum of use cases and interviewed those users to learn what they thought about Cloud Manager, how it compared to the old Linode Manager, and what they'd like to see in upcoming iterations.

Before

UX Design

I started with the dashboard, which I completely redesigned from the ground up to work well regardless of how many Linodes the customer managed. I incorporated content that most users would find useful and customized fleet representation based on the user's account.

Case Studies/Linode

Linode Cloud Manager

Designing an interface to manage a single VPS or a fleet of thousands

Vertical
Cloud Hosting
Platform
Responsive Web
Expertise
User Research / Information Architecture / UX Design / Usability Testing

Linode redesigned their admin panel for the first time in over a decade and its reception by longtime customers was mixed at best. I performed extensive research and addressed years of feedback, completely rethinking the product in the process.

Linode is an innovative cloud hosting provider that made their name as an affordable, developer-focused VPS service. Their browser-based administration panel, known as Linode Manager, was designed in-house by the company's engineers to be a fast, no-frills interface for customers to manage their virtual machines, domains, and other cloud assets.

As the cloud hosting industry grew, competitors joined the market with similar services. Linode Manager went without significant changes for over a decade aside from new functionality to accommodate a growing product line, allowing their competitors to surpass them with a far superior user experience. Not wanting to be left behind, Linode partnered with a creative agency to redesign Linode Manager to suit modern expectations.

The redesign was divisive, however, catering primarily to customers with larger fleets and lacking core features that were essential to many customers' workflows—so much so that Cloud Manager was kept in open beta for years as Linode Manager continued to be the default interface for many existing customers.

When I joined the company, I was determined to make Cloud Manager a great experience for all customers and finally sunset the old Linode Manager.

User Interviews

I partnered with Customer Success to identify users who represented a broad spectrum of use cases and interviewed those users to learn what they thought about Cloud Manager, how it compared to the old Linode Manager, and what they'd like to see in upcoming iterations.

As it turned out, many users found Cloud Manager a downgrade from the old Linode Manager for various reasons. They appreciated the new design's clean aesthetic, but bemoaned the reduced efficiency; adding copious amounts of white space led to a significant reduction in information density, and burying more complex tasks deeper in the interface catered to novices rather than experienced users—a big departure from the market segment that brought Linode its initial success.

UX Design

I set the following design goals:

  • 01Redesign the dashboard, list view, and detail view to provide useful information regardless of the customer's fleet size.
  • 02Reorganize the information architecture, paying particular attention to consistency in menus/actions across different screens and information hierarchy within each screen.
  • 03Improve clarity of and access to status and notifications.
  • 04Increase information density for easier scanning and decreased scrolling; it's a complex administration tool, not a marketing site.
  • 05Address accessibility issues related to the visual design.

I started with the dashboard, which I completely redesigned from the ground up to work well regardless of how many Linodes the customer managed. I incorporated content that most users would find useful and customized fleet representation based on the user's account.

Open source · MIT · sole author since 2013

citizen

An MVC-based web application framework designed for people interested in quickly building fast, scalable web sites instead of digging around Node's guts or cobbling together a wobbly Jenga tower made out of 50 different packages.

Use citizen as the foundation for a traditional server-side web application, a modular single-page application, or a RESTful API.

View on GitHub npm install citizen
Philosophy

Convention over configuration, but still flexible. A citizen app is a directory of controllers, models, and views that follow a naming convention; the framework infers the routes. There is no build step, no router to register, and no assembly of a dependency graph before the first page renders.

The framework has few direct dependencies, which is the point. Routing, static serving, session management, caching, compression, form parsing, and logging are all part of the framework rather than a package each. Views render with template literals out of the box, or any engine supported by consolidate.

Code reuse happens through includes and chaining. An include is a complete MVC pattern with its own controller, model, and views, delivered to the caller as fully rendered output, so logic stays in the controller rather than the template. Chaining passes a request through several controllers in series, each adding data and rendering its own view, which is how a global layout works without any special-casing.

Quick start
$ mkdir myapp && cd myapp
$ npm install citizen
$ node node_modules/citizen/util/scaffold skeleton
$ node app/start.js

The scaffolding utility generates a working app skeleton with an index pattern and error templates. A second command generates individual MVC patterns.

Capabilities
Zero-configuration routing

SEO-friendly URLs with name/value parameters instead of query strings, plus an optional descriptor slot that doubles as a unique identifier.

Content negotiation

HTML, JSON, JSONP, and plain text served from the same pattern based on the request's Accept header, so one resource backs both a page and an API.

Includes as components

Full MVC patterns used as includes, each with its own controller, model, and views. Any include is also addressable over HTTP.

Controller chaining

Chain any number of controllers in a single request, each with access to the previous context, with the last one rendering the final view.

Key/value cache

An in-memory store for requests, controller actions, objects, and static files, with per-item lifespans, access-based extension, and automatic ETag handling.

Session management

Server-side sessions with configurable lifespan, plus simple directives for cookies, redirects, and HTTP headers.

Hot module replacement

Saving a module or view in development mode re-imports it in real time. No restart, no lost state.

Application event hooks

Act on application, request, response, and session events, passing context down to the controllers that follow.

Graceful error handling

Errors are captured and returned in the format the route requested, with custom views per HTTP status code, without exiting the process.

ES and CommonJS modules

Both module systems are supported, along with compression, form parsing, CORS preflight responses, and file and console logging.

In production

Runs this site and originaltrilogy.com, which handles a few hundred thousand views a month on a $30 cloud hosting plan.

Stability

A single instance, with the process running for months at a time without crashing.
